Public-Key Generation on a Toy Elliptic Curve

Exploration of elliptic-curve scalar multiplication, using a small toy curve to understand the basic idea behind elliptic-curve public-key cryptography.

1. What is the goal?

Public-key cryptography uses a mathematically related pair of keys. The private key is secret, while the public key can be shared openly. In elliptic-curve cryptography, the public key is obtained by multiplying a public base point by a private scalar:

Q = kG

  • k is the private key, represented as an integer.
  • G is a publicly known base point on the curve.
  • Q is the public key, also a point on the curve.

Here, “multiplication” does not mean multiplying the point's coordinates by k. It means adding the point to itself repeatedly according to the elliptic-curve group law. For example, 3G = G + G + G.

The exercise uses k = 6. This tiny value is chosen only to make the calculations easy to follow. In Ethereum, a valid secp256k1 private key is an integer much larger than 6, normally represented using 32 bytes (256 bits).

2. The toy elliptic curve

Elliptic curves are mathematical objects defined by an equation with form: y² = x³ + ax + b. The main example uses the curve y² = x³ + 7 (mod 17), with base point G = (1, 5). Calculations are performed mod 17, so coordinate values are represented by integers from 0 to 16.

“Mod 17” means that results are reduced to their remainder mod 17. For example, 20 mod 17 = 3 and −3 mod 17 = 14. A pair (x, y) is a point on the curve only if it satisfies the curve equation.

We can check the chosen base point directly. For G = (1, 5), the left-hand side is 5² = 25 ≡ 8 (mod 17), while the right-hand side is 1³ + 7 = 8. The values agree, so G is on the curve.

The small modulus is for teaching purposes: it lets the program enumerate all the points and makes every operation inspectable. It is not cryptographically secure.

3. How point addition works

Elliptic-curve points have a special addition rule. Given two distinct points P = (x₁, y₁) and R = (x₂, y₂), first compute the slope using modular arithmetic:

λ = (y₂ − y₁) / (x₂ − x₁) (mod p)

Division modulo p means multiplying by the denominator's modular inverse. The resulting point S = P + R = (x₃, y₃) is then calculated as:

x₃ = λ² − x₁ − x₂ (mod p)

y₃ = λ(x₁ − x₃) − y₁ (mod p)

When the two points are equal, the operation uses the tangent slope instead. The implementation also handles opposite points, whose sum is the point at infinity O. This point acts as the identity element: P + O = P.

Worked example: computing 2G

Start with G = (1, 5). To compute 2G, add G to itself. Since this is point doubling, the slope is λ = (3x₁² + a)/(2y₁) (mod 17), where a = 0. Thus λ = 3 × 10⁻¹ (mod 17). The modular inverse of 10 is 12 because 10 × 12 = 120 ≡ 1 (mod 17). Therefore λ = 3 × 12 ≡ 2 (mod 17).

The new coordinates are x₃ = 2² − 1 − 1 = 2 and y₃ = 2(1 − 2) − 5 = −7 ≡ 10 (mod 17). Hence:

2G = (2, 10)

5. Why is the operation useful in cryptography?

The forward calculation, Q = kG, is efficient. The reverse problem—recovering k when G and Q are known—is called the Elliptic Curve Discrete Logarithm Problem (ECDLP). On a properly chosen real curve, solving this problem is believed to be computationally infeasible with classical computers at current security levels.

This is the asymmetry that makes elliptic-curve public-key cryptography useful: computing the public key from the private key is practical, while recovering the private key from the public key should be infeasible. However, the toy curve cannot demonstrate this hardness. For the selected point, the order is only 9, meaning 9G = O and the multiples repeat every nine steps. A few additions are enough to recover the scalar in this example.

The scalar is effectively considered modulo the order of the base point. On this toy subgroup, 6G = 15G because 15 mod 9 = 6. Real systems restrict private scalars to the appropriate valid range and use a group of enormous order.

7. Statistical exploration

The program repeats the calculation for many scalar values and reports several descriptive statistics. These tests help explore the behaviour of the outputs.

Coordinate distributions and frequencies

The program counts how often each coordinate value appears, how many distinct x and y values occur, and the mean coordinate values. The coordinates cannot be arbitrary pairs: every output must be a valid point on the curve. Over one complete cycle, every non-identity point in the subgroup generated by G appears exactly once, by construction.

Bit balance

Each coordinate is represented in binary, and the program measures the fraction of 1s at each bit position. This describes the observed sample, but a balanced bit count does not establish that the output is random or that the underlying operation is secure.

Correlation

Pearson correlations between k and the coordinates measure only linear association. A coefficient near zero does not mean that no relationship exists. Scalar multiplication has a clear algebraic structure: (k + ℓ)G = kG + ℓG and (k + 1)G = kG + G. Simple correlation tests do not capture all such structure.

Avalanche-like behaviour

The program flips one input bit at a time and counts how many bits change in the encoded output coordinates. Many cryptographic hash functions aim for a strong avalanche effect: changing one input bit should change about half of the output bits on average. Elliptic-curve scalar multiplication does not have this requirement, and its group structure does not guarantee a 50% change. Results on a tiny, periodic subgroup are particularly limited and must not be interpreted as a security test.

8. Encryption and decryption with the toy curve

The scalar multiplication above is only half of public-key cryptography. The other half is using a key pair to hide a message. The procedure below is the elliptic-curve version of ElGamal encryption, the same idea that underlies ECIES.

The idea

Bob has a private key dB and publishes the public key QB = dBG. Alice wants to send him a message encoded as a point M on the curve. Only Bob can recover M, because only Bob knows dB.

Encryption (Alice)

  1. Pick a fresh random number r with 1 ≤ r < n. It is used for this message only.
  2. Compute C1 = rG. This point is sent to Bob.
  3. Compute the shared secret S = rQB. Alice can do this because she knows r and QB.
  4. Compute C2 = M + S.

The ciphertext is the pair (C1, C2).

Decryption (Bob)

  1. Compute S' = dBC1.
  2. Compute M = C2 − S'.

This works because dBC1 = dB(rG) = r(dBG) = rQB = S. Bob obtains the same secret that Alice computed, without ever learning r, and subtracts it from C2.

Worked example on the toy curve

Curve y² = x³ + 7 (mod 17), base point G = (1, 5), order n = 9.

The ciphertext sent is ((2, 10), (5, 8)). Bob recovers M = (2, 7), the message Alice sent. The step −2G = 7G holds because −P = (x, −y), so −2G = (2, −10) = (2, 7), which is the same as 7G since 9G = O.

What the toy version does not show

  • An eavesdropper sees C1 = (2, 10) and C2 = (5, 8). To recover M they need S = rQB, which means solving the ECDLP for r or for dB. Here that takes at most 9 tries, because the order is 9. On secp256k1 it is infeasible.
  • The message is itself a curve point, so only 17 messages are possible, and the scheme is not practical. Real systems hash the shared secret to derive a symmetric key, encrypt the message with a symmetric cipher such as AES, and add an authentication tag. This is the structure of ECIES.
  • The random number r must be fresh for every message. If Alice reuses r for two messages, then C2(1) − C2(2) = M1 − M2, so the difference between the messages is revealed. Reusing a nonce is a classic failure.

9. Scalar multiplication versus cryptographic hash functions

Both scalar multiplication and cryptographic hash functions are deterministic and efficient to compute, but they serve different purposes. A one-way function is intended to be easy to evaluate and hard to invert. For elliptic-curve scalar multiplication, the relevant hardness assumption is the ECDLP. Statistics such as bit balance and apparent uniformity are not defining requirements of one-wayness and cannot demonstrate it.

A general-purpose cryptographic hash function accepts messages of arbitrary length and produces a fixed-length digest. It is designed to provide properties such as preimage resistance and, where required, collision resistance. Hash designs also aim to avoid simple exploitable algebraic structure. Scalar multiplication instead maps a scalar to a point in a group and deliberately follows the group's algebraic rules. An avalanche-like output pattern is desirable in many hash designs, but it is not a requirement for public-key scalar multiplication.

The main lesson from the statistical section is therefore not that the output “looks random”, but that statistical observations and cryptographic security are different questions. Security depends on the mathematical problem and the parameters, not merely on the appearance of sampled outputs.

10. Connection to Ethereum

Ethereum uses the secp256k1 curve for conventional externally owned account keys. The core public-key step follows the same idea as this exercise: a private scalar k is used to compute the public point Q = kG. The curve parameters and key space are vastly larger than those in the toy example.

An Ethereum address is then derived separately: Keccak-256 is applied to the 64-byte concatenation of the public key's x and y coordinates (without the uncompressed-key 0x04 prefix), and the last 20 bytes of the hash are used as the address. Therefore, the hash-related properties come from Keccak-256, not from elliptic-curve scalar multiplication.

11. Conclusion

This homework implements the mathematical path from a private scalar to a public point, checks the result using two multiplication methods, and explores the outputs through simple statistics. The toy curve makes the calculations visible, but its tiny subgroup also makes the reverse problem trivial. The essential cryptographic idea is that real elliptic-curve systems use carefully chosen parameters so that public-key computation is efficient while recovering the private scalar remains computationally infeasible. Statistical tests can illustrate behaviour, but they cannot replace a cryptographic security argument.
