From Wallet Seed to Ethereum Address

Hashing, key derivation and cryptographic primitives, followed step by step through the pipeline that Ethereum wallets use.

1. Overview

A wallet does not store one key. It stores a mnemonic phrase, and everything else is computed from it: a seed, a tree of keys, a private key, a public key, and finally an address. The whole pipeline is deterministic, so the same phrase always gives the same addresses, and this is why the phrase must be kept secret.

Mnemonic → BIP-39 → Seed → BIP-32 / BIP-44 → Private key → secp256k1 → Public key → Keccak-256 → Ethereum address → EIP-55 → Checksummed address

2. Task

Check the pipeline from a mnemonic phrase to an Ethereum address, and describe the role of BIP-39, BIP-32, BIP-44, secp256k1, Keccak-256 and EIP-55. The page below runs each step in the browser, so you can follow the intermediate values. The same steps are what software wallets such as MetaMask or Rabby perform internally.

3. Historical context

YearTechnologyRole in the pipeline
1977RSAFirst widely known public-key cryptosystem.
2001SHA-2 / SHA-512Standardized hash family, published by NIST as a draft in 2001 and as FIPS 180-2 in 2002.
2012BIP-32Hierarchical deterministic (HD) key derivation.
2013BIP-39Mnemonic phrases that encode the seed.
2014BIP-44Standard derivation paths for multiple accounts.
2015SHA-3 (Keccak)Standardized by NIST as FIPS 202, based on the Keccak design.
2016EIP-55Mixed-case checksum for Ethereum addresses.

secp256k1 is older than most of these: it is a curve defined in the SEC 2 standard (2000), and Bitcoin adopted it in 2009. Ethereum inherited it.

SHA-2 and Keccak / SHA-3 are not the same design

Both belong to the family of cryptographic hash functions, but they are built differently. SHA-2 uses the Merkle–Damgård construction. Keccak uses the sponge construction, and it won the NIST competition that produced SHA-3. Ethereum uses Keccak-256, which is not the same as the standardized SHA3-256: the two differ in the padding (domain separation) byte. 4. Distinctions

        
    
            
  • Key generation creates new randomness, here the 128 bits of entropy behind a mnemonic.
                Key derivation computes new keys deterministically from an existing seed, so one phrase
                gives an unlimited tree of accounts.
    • 
            
  • Public-key cryptography links a private key k to a public key
                Q = kG on secp256k1. Anyone can verify a signature with Q, but only
                the holder of k can produce it.
    • 
            
  • Hashing maps data of any length to a fixed-size digest. Here Keccak-256 maps
                the 64-byte public key to a 32-byte digest, and the address keeps the last 20 bytes.
    • 
            
  • Checksums detect mistakes. In BIP-39 the last word carries a checksum of the
                entropy; in EIP-55 the case of the letters in the address is a checksum of the address.
    • 
            
  • Encoding only changes the representation: mnemonic words, hexadecimal, and the
                mixed case of EIP-55 carry no secret and add no security. EIP-55 is a special case, because the
                case pattern is derived from a hash, so it carries information about errors.
    •

8. Discussion


        
Why the pipeline uses several techniques

        

            Each step solves a different problem, and no single primitive does all of them well.
        

        
    
            
  • BIP-39, BIP-32 and BIP-44 handle key management. BIP-39 turns 128 bits of
                entropy into words a person can write down, and PBKDF2 stretches them into a seed. BIP-32 derives
                a tree of keys from that seed, so one backup covers every account. BIP-44 fixes the layout of the
                tree (m / purpose' / coin' / account' / change / index; 60 is Ethereum's coin
                type), so different wallets find the same accounts. The hardened levels (') use the
                private key of the parent, so a leaked child key cannot reveal its siblings.
    • 
            
  • secp256k1 provides the link between private and public key. It is a one-way
                function that makes Q = kG easy to compute and k hard to recover, and it
                supports digital signatures. The address alone does not reveal the public key until the first
                transaction, which is an additional protection.
    • 
            
  • Keccak-256 compresses the 64-byte public key into a short identifier. Its job is
                not to hide the key, but to produce a fixed-size, well-distributed value with no algebraic
                structure. It is a hash, so it cannot be inverted, and it is applied after the curve step.
    • 
            
  • EIP-55 protects the address against typing errors. Ethereum addresses are 40 hex
                characters without a checksum, so an error would send funds to a wrong but valid address. The
                mixed case adds one bit of checking per letter in the address, with no change to the address itself.
    • 
        


        
Statistical properties

        

            For a hash such as Keccak-256, the key property is avalanche: a one-bit change in the input should
            flip about half of the output bits. The first test checks this, and the value is close to 50%.
        

        

            For secp256k1, the output also looks random bit by bit, but this is not a hash property. Scalar
            multiplication has algebraic structure: (k + 1)G = kG + G. Random-looking bits are
            therefore not enough to show that a function is suitable for every purpose, as discussed in
            HMWK 1.
        

        

            The address statistics show that the hex digits are close to uniform (chi-square below the 5% critical
            value), and that about half of the letters are uppercased by the checksum, as expected for a hash
            nibble above 7. The checksum catches every single-letter case change in the address, because each
            letter's case is fixed by the hash.
        


        
Comparison with wallet software

        

            Software wallets such as MetaMask, Rabby, Exodus or Rainbow implement this same pipeline. To compare
            them with the page, let a wallet generate a new phrase, note its first address for the default path,
            then enter that phrase in the page and check that the address matches. This means typing the phrase
            into a web page, so do it only with a throwaway phrase that will never hold funds, and delete the
            wallet afterwards.
